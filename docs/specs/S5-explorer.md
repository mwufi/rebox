# S5 — Explorer UI + admin API

**Goal:** a fast, good-looking explorer for the public graph (search, entity pages, neighborhood graph, query builder, review queue), served by the API, plus the admin endpoints (CONTRACTS §7) the review queue needs.

**Branch:** `s5-explorer`  **DB prefix:** `s5_`  **Depends on:** S1 merged to `main`.

## Owns
`apps/web/**`; in `apps/api`: new files `src/routes/admin.ts`, `test/admin.test.ts`, and the minimal registration lines in the existing router.

## Admin API (apps/api)
Implement CONTRACTS §7 exactly: review list with candidate EntityRefs, merge (cycle-safe: refuse merging into an entity that is itself merged, or into itself), split, dismiss. Each writes `merge_log` and a `change` row (`op` = `merge`/`split`). Admin token only.

## Explorer (apps/web)
React 18 + TypeScript + Vite + react-router. Package `@rebox/web`; `build` writes to `../api/public`. Typed API client generated by hand from CONTRACTS §6 (one `api.ts`). No UI framework beyond a small CSS file with design tokens; light and dark themes.

Pages:
1. **Home** `/`: graph size (from `/v0/stats`), a big search box, recently changed entities (from `/v0/changes`), and a few example queries as links.
2. **Search** `/search?q=&kind=`: results grouped by kind, keyboard navigable.
3. **Entity** `/e/:id`: name, kind, key attributes on top (description, website, domain, YC batch, founded year); edges grouped by predicate with linked EntityRefs and date ranges; incoming edges; every fact shows a small source badge (layer) with `source_ref` on hover; "merged from" note; link to the graph view. Follow merge redirects.
4. **Graph** `/e/:id/graph`: 1-hop neighborhood (optionally 2-hop for small degree) drawn with d3-force in SVG, nodes colored by kind, click to navigate, hub nodes capped (show "+N more").
5. **Query** `/query`: builder for the §6 filter list (find kind; add rows: name contains, edge predicate/direction/to/during, attribute eq/gte/lte/contains), results with reasons, state encoded in the URL so queries are shareable.
6. **Review** `/review`: asks for the admin token (kept in sessionStorage only), lists open review items with side-by-side candidate summaries, merge/dismiss actions.
7. **API** `/api`: the endpoint list with copyable curl examples against the current host.

Design: load the `frontend-design` skill guidance if you can. Aim for a calm, information-dense, distinctive look (good typography, clear hierarchy, source badges that read at a glance); it must feel fast (no layout shift, skeletons while loading) and work on a phone width.
